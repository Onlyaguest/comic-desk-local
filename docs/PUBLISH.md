# 发稿台

在桌面右上角点 **✍**，或打开 `http://127.0.0.1:7777/publish/`。

写稿交给 AI 以后，人要做的事情其实很固定：挑一版、改几处、拿去别的编辑器再顺一遍、发出去、把链接记下来。发稿台把这些事排成一条流程条，每一步旁边放好按钮。它不替你写稿，也不替你点发布。

## 一篇稿的 7 步

| 步 | 做什么 | 按钮 |
|---|---|---|
| 写稿 | 看稿子在不在；同一篇有另一版时提示 | 和另一版并排比 |
| 验收 | 照自己的清单看一遍，记下过 / 要改 | 标记验收过 / 标记要改（个人模式可配「跑检查」） |
| 我来改 | 把你改好的段落或一句要求写进框里 | 按我这段重写整篇 / 只改这一处 / 以后都这样 |
| 外部改 | 导出一份，拿去任何编辑器或云文档改，回来看改了哪 | 导出去改 → 看改了哪 → 采用外改版 |
| 挑这版 | 两版里挑一版 | ⭐ 挑这篇要发 |
| 发出去 | 复制标题和正文去平台发 | 复制标题 / 复制正文 / 我发出去了 |
| 归档 | 填上原文链接 | 填链接 / 归档 |

**「我来改」不调用任何 AI**：你写的原话会记进这篇稿的 `.desk/调整.jsonl`，页面同时给你一段可以复制的话（写清了怎么改、稿子在哪、以前提过的要求在哪），粘给你自己的 AI 助手就能开工。

**「外部改」怎么对比**：导出时会留一份底稿（`.desk/外改底稿.md`），你改的是 `.desk/外改.md`。页面按段落对比这两份，标出新加、删掉和段内改动的字（用 Python 自带的 difflib）。要你点「采用」才会写回定稿，旧稿先存进稿件目录的 `历史/`。图片按「第几张」对回本机文件，云文档里的图片链接不会写进定稿。导出以后定稿又被改过时，页面会先提醒你。

## 离线样例

默认是离线样例：首次打开时，把 `samples/publish/` 复制到 `data/publish/demo/`（不进 Git），之后所有改动都只写在那里。样例里有 4 篇虚构的稿：一篇外部改过、等你采用，一篇是它的另一版，一条灵感，一篇已发出。样例模式**不调用任何外部命令、不联网**。想重来，删掉 `data/publish/demo/` 就行。

## 接自己的稿子（个人模式）

新建 `data/publish/config.local.json`（`*.local.json` 不进 Git）：

```json
{
  "posts": "/完整路径/posts.json",
  "root": "/完整路径/稿件根目录",
  "commands": {
    "preview": ["/完整路径/我的排版预览脚本", "{pack}"],
    "fetch": ["/完整路径/从云文档导出markdown的脚本", "{id}"]
  }
}
```

- `posts`：登记表，一个 JSON 数组，一篇一条，格式见下面。
- `root`：登记表里的相对路径从这里算，不写就是登记表所在的目录。所有路径都只能落在这个目录里面。
- `commands`：可选，只认 `preview`、`check`、`export`、`fetch` 这四个名字。命令不经过 shell 执行，占位符只有 `{pack}`（稿件目录）、`{body}`（正文文件）、`{id}` 和 `{out}`（`.desk/外改.md`）。`fetch` 的标准输出会存成 `.desk/外改.md`，命令参数里写了 `{out}` 时就由命令自己写这个文件。比如接飞书时，`export` 写成「把正文建成飞书文档」，`fetch` 写成「把那篇飞书文档导出成 markdown」，这样在飞书里改完，点「拉回改动」就能对比。

登记表一条长这样（字段都可以省，`id` 必填）：

```json
{"id": "desk-intro", "title": "我给自己搭了一张本地桌子", "platform": "公众号", "account": "我的号",
 "status": "待发", "date": "2026-11-01", "by": "模型 A",
 "pack": "packs/2026-11-01_desk-intro", "body": "packs/2026-11-01_desk-intro/article.md",
 "qa": "过 · 清单 6 条", "picked": false, "url": "", "note": "一句话：卡在哪"}
```

- `status` 只用五档：`灵感`、`草稿`、`待发`、`已发出`、`已归档`。
- 正文用 markdown，开头可以带 `---` 信息头（`title`、`digest`、`cover`……）；采用外改版时会保留信息头，外改版改了标题或摘要就跟着改。
- 两版怎么认：同一平台、稿件目录名只差 `-v2`、`-gemini`、`-opus` 这类后缀的，或者写了同一个 `versionOf` 的，算同一篇的两版。

## 接口

`GET /api/publish/state`、`/api/publish/post?id=`、`/api/publish/diff?id=`、`/api/publish/file?id=&p=`（只给这篇稿目录里的图片）；`POST /api/publish/action`，`op` 可以是 `pick` / `status` / `url` / `qa` / `note` / `export` / `adopt` / `run`。和桌面其他写接口一样，只绑本机地址、拒绝跨源。
